# 修改意见：为「已过期但无截止时间」的条目获取真实任务时间段

> 状态：部分已落地（安全子集），完整方案待取证后实现
> 关联：`src/models.ts`、`src/chaoxing.ts`（exam-list 解析）、`entrypoints/background.ts`、`entrypoints/popup/App.tsx`
> 触发：用户截图——学习通「作业/考试列表」里状态为「已过期」的条目在看板显示「未提供截止时间」（无 dueAt）

---

## 1. 现象

- 学习通「作业/考试列表」（`mooc1.chaoxing.com/.../exam-list`）是**作业 + 测验 + 课堂活动**混合列表，该页**不渲染截止时间**（2026-10-29 已取证，代码注释明确：`// 该页不显示截止时间`）。
- 因此 `mapChaoxingExamAssignments` 对这一类条目一律设 `dueAt: null`，状态按平台文案映射为 `status: 'expired'`（已过期）。
- 看板里这些条目显示「未提供截止时间」，且**无论是否开启「自动隐藏已过期项」都一直显示**——因为当前过期判定只靠 `isAssignmentExpired(dueAt)`，`dueAt` 为 `null` 时永远返回 `false`。

---

## 2. 根因

| 环节 | 现状 | 后果 |
|---|---|---|
| exam-list 页面 | 不渲染截止时间（平台限制） | 解析器拿不到时间 |
| `mapChaoxingExamAssignments` | 诚实设 `dueAt: null`（不臆造，正确） | 无 dueAt |
| 过期判定 | `isAssignmentExpired(dueAt)` 只看截止时间 | `null` → 永远“未过期” |
| 「自动隐藏已过期项」开关 | 复用上面的判定 | 平台已标「已过期」的条目反而不被隐藏 |

矛盾点：**平台已经在状态上明确说了“已过期”**，但扩展只用“截止时间”判过期，等于把平台给的权威信号丢弃了。

---

## 3. 本次已落地的安全修复（已完成，2026-10-29）

在 `src/models.ts` 新增两个纯函数，并把后台角标/通知、弹窗看板三处计数统一到同一口径：

- `isAssignmentExpiredByStatus(status, dueAt)`：`status === 'expired'` 时**直接判为已过期**（状态权威），其余仍按 `dueAt` 判定。
- `isAssignmentVisible(a, { hideExpired })`：默认隐藏 `completed`/`ended`；开启「自动隐藏已过期项」时再隐藏已过期条目（含 `status === 'expired'` 的）。
- `entrypoints/background.ts` 的 `summarizeVisibleAssignments`、弹窗 `App.tsx` 的两处过滤（主列表 + 各平台徽标）全部改用 `isAssignmentVisible`。

效果：
1. **问题 1（计数一致）顺带解决**：角标/通知/看板三者「未完成 N 项」现在共用同一函数，不再出现“角标 58、看板 19”。
2. **问题 2 的安全子集解决**：开启「自动隐藏已过期项」后，`status: 'expired'` 的条目会从看板与角标消失（不再显示“未提供截止时间”占位）。

> 注意：这部分只解决了“该不该显示”，**没有**解决“它的真实起止时间是多少”。后者见第 4 节。

---

## 4. 尚未完成：获取真实「任务时间段」（开始/结束时间）

用户希望这类条目能显示具体的任务时间段（像任务页那样有「结束时间：MM-DD HH:MM」），而不仅是“已过期”一个状态。

### 4.1 为什么不能现在直接写死

- 现有架构的核心原则是**「先取证、再落地」**：没有真实 DOM / 接口证据不写解析逻辑，宁可 `needs-verification` 也不臆造。
- exam-list 条目要拿到时间，必须进入它的**明细页**（点每个条目）。但学习通里「考试」类明细页 = **答题页**，进入有触发答题/交卷风险，违反铁律**「绝不进入考试答题页、绝不点交卷」**。
- 因此「自动逐条进明细页抓时间」不能直接做，必须先区分明细页类型。

### 4.2 候选方案与风险

| 方案 | 思路 | 安全性 | 可行性前置 |
|---|---|---|---|
| **A（首选·安全子集）** | 复用 `readNoticeDetailText` 的「隐藏同源 iframe 读已渲染 DOM」机制，对**非考试类**条目（作业/测验/课堂活动）进明细页读时间窗；考试类排除 | 高（不进答题页） | 需先用 `diagnose.ts` 对学习通四类明细页分别取证，确认哪些是只读详情页、哪些是答题页 |
| **B** | exam-list 加载时通常伴随一个返回时间窗的 XHR 接口；从 `diagnose.ts` 已捕获的 `requests` 里找该接口，直接 fetch（只读、安全） | 高 | 需诊断确认接口 path 与返回结构 |
| **C（兜底·不推荐）** | 用“同步时刻 − 默认窗口”合成 `dueAt` | 低（臆造时间，违背 `dueAt 必须 null` 原则） | 仅做临时显示，不建议入库 |

### 4.3 推荐落地顺序

1. **先做诊断取证**（方案 A/B 的可行性验证）：在「作业/考试列表」页运行诊断，重点看
   - 每个条目的明细链接指向哪类页（详情页 vs 答题页）；
   - 网络请求里有没有返回起止时间的接口（方案 B）。
2. 若方案 B 接口存在 → 直接 fetch，零风险，优先实现。
3. 否则按方案 A：只对**确认是只读详情页**的条目（作业/测验/课堂活动）用隐藏 iframe 抓时间，有界并发（参考 `mapWithConcurrency` 默认 5），单条失败诚实降级为 `dueAt: null`、保留 `status: 'expired'`。
4. 考试类条目维持现状（`status: 'expired'` + `dueAt: null`），靠状态驱动隐藏，不进答题页。

---

## 5. 可选的显示增强（低优先级）

`formatDate(null)` 对无截止时间的条目一律显示「未提供截止时间」。对 `status === 'expired'` 的条目，改显示「已过期（平台标记）」会比“未提供截止时间”更贴近事实、也避免暗示“只是没抓到”。属纯展示优化，可在方案 A/B 落地后一并处理。

---

## 6. 验证口径

- 在「作业/考试列表」页同步后：开启「自动隐藏已过期项」→ 这些 `expired` 条目应从看板列表、角标、通知一起消失；关闭则恢复显示「已过期 / 未提供截止时间」。
- 角标数字 == 看板「未完成 N 项」== 通知主数字，三者一致。
- `npm run compile` / `npm test`（新增 `isAssignmentExpiredByStatus`、`isAssignmentVisible` 用例）须通过。
