# 学习通任务“是否完成”判定规则（规格文档）

> 用途：指导后续把学习通“任务完成状态”解析器落地到 `src/chaoxing.ts`。
> 本文档是**判定规格**，不是实现；诊断工具（`src/diagnose.ts`）已按此规格扩展，可先在
> 泛雅课程页取证，再据证据回填解析器。
> 生成日期：2026-10-25。

## 0. 核心结论

当前学习通模块**只能解析收件箱通知**（`notice.chaoxing.com`），收件箱天生不含“你已提交没提交”
的信号，因此**无法判定任务是否完成**（作业永远是 `unsubmitted`，考试只按截止时间分
`unsubmitted`/`expired`，`expired` ≠ 已完成）。

要真正判定完成，必须读取**泛雅课程页**里带提交状态的列表：
- 课程内「作业」列表页 / 「考试」列表页（权威提交状态）
- 课程内「任务」列表页（活动窗口状态，按用户拍板简化判定）

收件箱模块降级为“新任务发现 + 考试截止时间”的辅助信号，**提交状态一律以课程列表页为准**。

## 1. 数据源与判定优先级（每门课）

```
数据源优先级（每门课）：
  作业列表页（全部视图）──► 权威提交状态
  考试列表页（全部视图）──► 权威提交状态（含重考特判）
  任务列表页           ──► 仅取"进行中"条目 + 截止时间（辅助）
  收件箱通知           ──► 降级为"新任务发现"，状态以列表页为准
```

## 2. 域名与入口（已加进 `wxt.config.ts` 与 `content.ts`）

| 入口 | 域名 | 说明 |
|---|---|---|
| 我的课程（课程枚举） | `mooc1.chaoxing.com/visit/stucoursemiddle?courseId=..&classId=..` | 拿到全部课程的 `courseId`+`classId`+课程名 + “任务点进度 x/y” |
| 课程页外壳（左侧菜单） | `mooc2-ans.chaoxing.com/mooc2-ans/mycourse/stu?courseId=..&clazzid=..` | 仅渲染顶部导航与左侧菜单，**作业/考试/任务列表在跨域 iframe 里，不在主文档** |
| 任务(活动)列表 iframe | `mobilelearn.chaoxing.com/page/active/stuActiveList?courseid=..&clazzid=..&cpi=..&stuenc=..` | **权威内容帧**，诊断/解析必须读此帧 |
| 作业列表 iframe | `mooc1.chaoxing.com/mooc2/work/list` | 左侧菜单 `作业` 的 data-url（诊断取证得到） |
| 考试列表 iframe | `mooc1.chaoxing.com/exam-ans/mooc2/exam/exam-list` | 左侧菜单 `考试` 的 data-url |
| 收件箱（现有） | `notice.chaoxing.com/pc/notice/myNotice` | 仅通知，无提交状态 |

> ⚠️ **关键架构事实（2026-10-25 诊断证实）**：课程页 `mooc2-ans.chaoxing.com` 主文档只含导航/菜单，
> 真正的作业/考试/任务列表由 SPA 加载进 `mobilelearn.chaoxing.com` / `mooc1.chaoxing.com` 的**跨域 iframe**。
> 因此：① 诊断必须捕获该内容 iframe 帧（不能只取外壳主文档）；② 正式解析器要在内容 iframe 上下文运行
> （`content_scripts` 已 `allFrames:true`，需在 `chaoxing` 适配器里按 `mobilelearn/mooc1` 域放行）。
> 上述内容端点来自课程页左侧菜单 `<a data-url="…">` 的诊断证据，落地时优先直接用这些路径构造 URL，
> 比解析菜单更稳。

> 注意：`我的课程` 页用 `classId`，课程页用 `clazzid`——落地时统一字段名并验证是否同值。
> “任务点进度 x/y”是**章节视频学习进度**，不是作业/考试提交状态，二者不得混用。

## 2.1 任务/活动列表真实 DOM（2026-10-25 取证，已落地为解析器）

取证方式：诊断工具捕获外壳主文档里的内容 iframe URL（含左侧菜单 `a[data-url]` + 外壳查询参数），
**开临时后台标签以顶层文档方式诊断**——跨域帧注入（`allFrames` / `frameIds`）在部分环境静默失败，
顶层文档注入不受影响。样本（课程「25数据科学34」）：

```
div.main.task-list
├─ div.top-back > h2#classObjName          → 课程名「25数据科学34」
└─ div.has-content > div.bottomList
   ├─ div.status 「进行中（0）」            → 分组标题，括号内为计数
   ├─ ul（该组条目，本例为空）
   ├─ ul
   ├─ div.status 「已结束（15）」
   └─ ul
      └─ li × 15
         ├─ div.tag.icon-tp                （通用任务图标）
         ├─ div.tag.icon-signin-g | icon-xr-g   （签到 / 选人）
         ├─ div.right-content > p          → 标题（普通签到 / 选人 / 位置签到）
         └─ div.time                       → 「结束时间：05-20 08:06」（无年份）
```

已落地的解析（`src/chaoxing.ts`）：

| 环节 | 实现 |
|---|---|
| 路由 | `extractChaoxingAssignments` 按 `hostname === 'mobilelearn.chaoxing.com' && pathname 含 stuActiveList` 路由 |
| 课程标识 | URL 查询参数 `courseid` + `clazzid` → `259363438-139380153`（稳定）；缺失时降级课程名 slug |
| 分组识别 | 遍历 `.bottomList` 直接子元素：遇 `.status` 切换分组，遇 `ul` 收集其 `li` |
| 单条 | 标题 `.right-content p`、类型 `.tag[class*=icon-]`、时间 `.time` |
| 时间归一 | `normalizeChaoxingTaskDeadline`：`MM-DD HH:mm` 缺年份 → 用当前年补齐；已结束项若补齐后落在未来则回退上一年 |
| 状态映射 | 「进行中」→ `in_progress`；「已结束」→ `ended`（默认隐藏，符合判定表） |
| ID | `chaoxing:<courseid-clazzid>:task:<hash(分组｜类型｜标题｜截止文本)>`，跨会话稳定、可去重 |

ID 分工（阶段 A 课程注册表落地前的过渡约定）：
- `assignment.courseId` 用**课程名 slug**（与收件箱路径一致，保证同一门课在看板里只有一个分组）；
- 合并作用域 `courseIds` 用**稳定的 `courseid-clazzid`**，不会误清收件箱里同课程的作业通知。
- 遗留：教师删除活动后旧项不会自动消失（作用域不覆盖课程名分组），待阶段 A 统一 ID 后修复。

### 2.2 任务页是「混合列表」：它聚合了作业/测验（2026-10-25 第二批诊断）

数据库原理与技术（`courseid=266109891&clazzid=152005723`，页面标题「数科25003-25004班」）
的任务页 12 条里，**11 条标题写着「作业」**（`10.19日作业：…提交学习通作业`），图标为 `icon-cy-g`，
另有 1 条「二维码签到」`icon-signin-g`。公网资料也印证：学习通课程内「任务」标签会显示该课程的
**作业、测验、活动等**。

| 图标 | 含义 | 备注 |
|---|---|---|
| `icon-tp` | 通用任务（每条都有） | 仅当没有更具体的图标时才用它 |
| `icon-signin-g` | 签到 | 已实证 |
| `icon-xr-g` | 选人 | 已实证 |
| `icon-cy-g` | **作业或测验**（中性标签） | 任务页聚合的作业/测验类；语义未 100% 锁定，故不臆测为「测验」 |

**用户最终拍板（2026-10-25）**：任务页「已结束」→ **直接判定为已完成**，不再区分活动还是作业/测验，
看板默认隐藏。代码：`mapChaoxingTaskAssignments` 中 `已结束 → status='ended'`；
`assignmentStatusLabel('ended') === '已完成'`；`isAssignmentHiddenByDefault('ended') === true`。
类型标签仍保留「作业或测验」（仅用于标题与稳定 ID，不影响判定）。

**交叉验证（可选，不阻塞）**：任务页顶部有「全部 / 已完成 / 未完成」筛选。若点「未完成」后重新诊断，
过滤后剩下的条目即为真未完成；如实证存在“已结束但未提交”的作业，再回过头修订本条判定。

### 2.3 作业/考试列表真实 DOM（2026-10-29 取证，已落地为解析器）

端点（诊断取到的真实地址，非猜测）：

```
https://mooc1.chaoxing.com/exam-ans/mooc2/exam/exam-list?courseid=<courseId>&clazzid=<clazzId>&v=2&hideHead=0&pageHeader=0
```

三个反直觉的实测结论：

1. **页面标题叫「考试列表」，内容却是作业 + 测验 + 课堂活动混合列表**。
   实测 10 行：`线代作业1..4`、`线代测验1..4`、`课堂学习活动（第三章/第三章、第四章）`。
   全部行的图标都是 `icon-exam-g` —— **图标无区分度，类型只能从标题推断**（`inferChaoxingExamType`）。
   因此它是作业进看板的**唯一来源**。
2. **`mooc1.chaoxing.com/mooc2/work/list` 实测不可用**：打开后 `title="提示"`、正文 0 字、0 行，
   只有一叠隐藏弹窗模板。故不抓该页（路由仍保留显式说明，避免被误当成解析失败）。
3. **该页不显示截止时间**（任务页有「结束时间：MM-DD HH:MM」，本页没有）。
   → `dueAt` 一律 `null`，不拿同步时间冒充；标题也不拼时间。

每行结构（与任务页**相反**，照抄任务页解析器会读到 0 条）：

```html
<div class="bottomList">
  <ul>
    <li>
      <div>
        <div class="right-content">
          <div class="tag icon-exam-g"></div>
          <p class="overHidden2 fl">线代作业4</p>   <!-- 标题 -->
          <div class="clear"></div>
          <p class="status fl">已完成</p>            <!-- 状态：每行各一个 -->
        </div>
        <div class="clear"></div>
      </div>
    </li>
  </ul>
</div>
```

坑①：**没有「进行中/已结束」分组**，状态在每个 `li` 内部（任务页是在 `.bottomList` 的直接子 div 上切 section）。
坑②：`p.overHidden2`（标题）与 `p.status`（状态）是**兄弟**，取 `.right-content p` 的第一个会把状态当标题。

实测状态文案只有 `已完成` / `已过期`；判定表里的 `未完成` / `待批阅` / `已退回` / `重考` 尚未在本页见到，
映射函数（`mapChaoxingExamStatus`）已按判定表预留，**认不出的返回 `null` 并计入未识别行，绝不猜成已完成**
（猜成已完成会把真实待办隐藏掉）。

安全阀：`bottomList` 有行、但一条都认不出来 → 抛 `SelectorError`（硬失败），
避免返回「空列表」被后台当成"教师删光了作业"而清空该课缓存。


## 3. 判定表（最终版，用户已确认）

| 页面显示 | 判定 | 看板处理 |
|---|---|---|
| 作业/考试：`未完成`、`未交` | 未提交 | 显示“待提交” |
| `待批阅` | 已提交未批 | 已完成，隐藏 |
| `已完成`（无重考按钮） | 已完成 | 隐藏 |
| `已完成` + `重考`按钮/提示重做 | 已完成，可重考 | 显示“已完成（可重考）” |
| `已退回` | 需重交 | 显示“需重交” |
| 任务页 `进行中` | 窗口内待做 | 显示，用其截止时间 |
| 任务页 `已结束` | **直接判定为已完成**（用户 2026-10-25 最终确认，不再区分活动/作业） | 隐藏，不显示 |

### 状态枚举（`models.ts` 已扩展，2026-10-25 落地）

`Assignment.status` 由 `unsubmitted | expired` 扩为：

| 状态 | 含义 | 看板标签 | 是否默认隐藏 |
|---|---|---|---|
| `unsubmitted` | 未提交 | 未提交 | 否 |
| `expired` | 已过截止（仍可作答） | 已过期 | 受「自动隐藏已过期项」开关控制 |
| `in_progress` | 任务页「进行中」 | 进行中 | 否 |
| `submitted` | 已交待批 / 待批阅 | 已提交 | 是 |
| `completed` | 已批阅 / 已完成且无可重考 | 已完成 | 是 |
| `ended` | 任务页「已结束」且无提交状态 | 已完成 | 是 |
| `returned` | 已退回 → 需重交 | 需重交 | **否**（必须显示） |
| `retake` | 已完成但有重考入口 | 已完成（可重考） | 否 |

配套纯函数（均在 `src/models.ts`，可单测）：
- `assignmentStatusLabel(status)` → 中文标签；
- `isAssignmentHiddenByDefault(status)` → 仅 `completed` / `ended` 为 true（判定表「已完成，隐藏」）。

> `expired` 刻意**不**在默认隐藏之列——它由独立开关控制，与「已完成」语义不同（错过截止 ≠ 做完了）。

## 4. 课程枚举前置（先有课程清单，才有稳定 ID）

稳定 ID 方案分两阶段：
1. **阶段 A · 课程注册表**（已落地 2026-10-25）：解析「我的课程」页 → 本机缓存
   `[{courseId, clazzId, 课程名, 任务点进度}]`；6 门课实测「线性代数」= 259363438 / 139380153，
   与课程页 URL 交叉验证一致。
2. **阶段 B · 逐课解析**（2026-10-29 落地「任务/活动列表」这一路）：按注册表拼
   `https://mobilelearn.chaoxing.com/page/active/stuActiveList?courseid=<courseId>&clazzid=<clazzId>`，
   由后台**顺序开临时后台标签**逐门取数，抓完立即关标签；弹窗注册表下方
   「逐课同步 N 门课」一键触发，用户不必手动进每门课。
   - 单门课等待上限 25s；失败只在“列表未渲染”（解析器内等 3s 不够）时重试一次，
     超时（多半未登录/网络不通）不重试，避免白开标签。
   - 抓取期间定时 `getPlatformInfo()` 保活，防止 MV3 后台在几十秒的批量流程中被回收。
   - **ID**：`chaoxing:<courseId>-<clazzId>:task:<hash(类型|标题|截止文本)>`；
     哈希**不含“进行中/已结束”分组** —— 活动到点只是状态迁移，不应换身份。
   - 看板分组键 `assignment.courseId` 仍用课程名 slug（与收件箱通知同源，保证一门课一个分组）；
     合并作用域用稳定的 `<courseId>-<clazzId>`。`mergeAssignmentsByCourse` 因此要**同时**
     按 `courseId` 和作业项 id 里的 `:<key>:` 边界匹配（按 `:key:` 而非 `includes(key)`，
     避免 2593634 误匹配 259363438）。若只比对 courseId，两个键永不相等 → 单课程合并形同失效，
     表现为“活动已结束但看板还在进行中”“教师删掉的活动永不消失”。
   - 本阶段仍未解决：课程被教师**整个删除**时注册表会更新、其条目随之失去作用域；
     该边界留到作业/考试解析器落地后一并处理。

> 直接爬取课程列表是阶段 A 的前提；不要在没有课程清单时下结论。

## 5. 完整性校验（复用现有范式）

- 作业页带 “已完成 X/Y” 或 “2/2” 进度汇总：解析条数与状态分布必须与汇总一致，
  否则按项目惯例报 `needs-verification`，**不覆盖缓存**。
- 任务页带 “进行中 (N) / 已结束 (N)”：done = 已结束数，total = 进行中 + 已结束，同样做一致性校验。

## 6. 安全与隐私边界（不可违反）

- 诊断工具与正式解析器都**只读列表页 DOM**，绝不进入“考试答题页”、绝不点“交卷/进入考试”
  启动答题（铁律）。诊断工具主动点击的左侧菜单「任务/作业/考试」只是打开列表视图，安全。
- 解析以**可见文本锚点**为主（如 `已完成/未完成/待批阅/已退回/重考/进行中/已结束`），
  少依赖会变的 CSS 类名（对齐 iTEST 路线）。
- 不猜未出现的 API 路径/字段；新结构必须先跑诊断取证再落地（项目硬规矩）。
