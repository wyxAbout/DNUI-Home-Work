## 2. 逐项方案

### 2.1 补 LICENSE

**现状**
- `README.md`「已知限制」第 108 行明确写着：“当前仓库**未添加开源许可证**（默认保留所有权利）”。
- 「许可证」章节（110–112 行）写“暂未指定（All rights reserved）”。
- 仓库根目录（`.git` 所在：`D:/Users/lenovo/Desktop/作业集合`）无 `LICENSE` 文件。
- `package.json` 仍是脚手架默认值：`"name": "wxt-react-starter"`、`"version": "0.0.0"`、`"private": true`，无 `license` 字段。

**问题**：默认“保留所有权利”等于禁止他人使用/修改，与“想让人用”的目标矛盾。

**方案**
1. 在仓库根新增 `LICENSE` 文件。推荐 **MIT**（对单人学校项目最友好，允许随意使用/修改，仅要求保留版权声明）。备选：Apache-2.0（含专利条款）、MPL-2.0（文件级 copyleft）。
2. 填写版权人（你的名字/GitHub ID）与年份（2026）。
3. 更新 `README.md`：删除/改写「已知限制」第 108 行；「许可证」章节改为指向 `LICENSE` 并说明授权范围。
4. 顺手规范化 `package.json`：`name` 改为项目名（如 `assignment-integration-dashboard`）、`version` 升为 `0.1.0`、加 `"license": "MIT"`、去掉 `"private": true`（或保留 private 但补 license 字段，二者不冲突）。

**涉及文件**：`LICENSE`（新增，仓库根）、`extension/README.md`、`extension/package.json`

**风险/验收**：几乎无风险；验收 = 仓库根有 LICENSE、README 不再自述“未添加”、`npm run compile` 不受影响。

**待确认决策**：许可证类型（默认建议 MIT）。

### 2.3 选择器配置化 + 失效显式报错（核心技术债）

**现状与问题（已用代码核验）**
- 选择器全部硬编码在四个解析器内部，散落各处：
  - `chaoxing.ts`：`li.dataBody_item`、`li[data-id]`、`.notice_title`、`.receiverName`、`.openNotice[data-url]`、`.notice_time`（343–355、478 行）。
  - `neusoft.ts`：`.v-content-wrap`、`.my-task`、`.v-layout-content`、`.el-tabs__item`、`.el-empty/.neu-empty/.noData…`（325–327、190–210、300 行）。
  - `pigai.ts`：`ul.reItemS`、`li.showST`、`li.stu_title a`、`#essayList`、`#pigai_nickname`（130–195 行）。
  - `itest.ts`：`[class*="stuClsInfo"]`（177 行）。
- “学校一改版就全哑”的根因：选择器与解析逻辑耦合，改版后要么解析为空、要么抛错，且**当前对“列表没渲染/结构已变”的兜底不足**：
  - `chaoxing.ts` 第 478 行 `ready()` 等待后**不校验是否真的渲染成功**，直接 `readRawItems`；若列表没出来 → 返回 `success` + `replaceAll:true` 空数组（525–532 行）→ **静默清空该平台历史缓存**。这就是“失效时静默跳过/覆盖”的最坏情形。
  - `neusoft/pigai/itest` 也有 `replaceAll:true` 空态返回（neusoft 433–440、pigai 220–231、itest 284–287），但大多有“空态标记”或“区块存在”前置判断；风险在于“结构变化导致解析为空”被误判为“真的为空”。
  - `content.ts` 第 50 行 `if (!result) return;`：`null` 是“本页与作业无关”的静默跳过——对“错误路径/错误 host”是对的，但**与“解析器本应处理却放弃”无法区分**，也没有把失败暴露给用户。

**方案**
1. **选择器外置为配置**：新增 `src/selectors.ts`，定义
   ```ts
   export interface SelectorConfig {
     // 关键结构锚点（用于“是否渲染成功”的判定）
     listContainer: string;
     item: string;
     fields: Record<string, string>; // title/time/url/status 等
     // 可选：分页、空态、回退选择器
     pagination?: { next: string; pageInfo?: string };
     emptyMarker?: string;
     fallbacks?: string[];
   }
   export const PLATFORM_SELECTOR_CONFIG: Record<PlatformId, SelectorConfig> = { ... };
   ```
   四个解析器改为**从配置读取**选择器，不再写死字符串。改版时只改这一个文件。
2. **建立“显式报错、拒绝静默”契约**：在 `platforms.ts` 或 `models.ts` 定义 `SelectorError`，并提供 `requireSelector(doc, sel, label)` 助手：
   - 在“有界等待后仍找不到关键结构锚点”时抛出 `SelectorError(label)`；
   - 解析器 catch 后转换为 `needs-verification`（**不是 `null`、不是 `success` 空数组**），消息里**点名是哪个选择器、哪个 host 没命中**，例如：“学习通收件箱：`li.dataBody_item` 未渲染（可能平台已改版或网络慢），未更新数据”。
3. **明确三种结果语义**（写进解析器规范/注释）：
   - `null`：本页确实“不是本平台的作业页”（错误 host/path）→ 静默跳过，**允许**。
   - `needs-verification` / `error`：**本页是本平台作业页、但结构缺失/解析不全** → **必须显式报错**，进入看板状态与日志，绝不覆盖缓存。
   - `success` + `replaceAll:true`：**仅在已确认“列表确实渲染且为空”**（命中空态标记，或分页已读到末页且 0 条）时才允许；否则一律 `needs-verification`。
4. **修复 chaoxing 静默清空 bug**：第 478 行 `ready()` 等待后，若 `li.dataBody_item` 仍未出现 → 返回 `needs-verification`（命名选择器），不要走 525–532 的 `replaceAll` 空返回。
5. **加 `selectorsVersion` 常量**（放在 `selectors.ts`）：每当选择器调整就 +1；在诊断工具（`diagnose.ts`）与平台快照 `message` 里带上，让用户能区分“数据是旧选择器留下的”还是“真的没作业”。
6. **防回归测试**：为四个解析器补测试——构造“关键结构锚点缺失”的假 DOM，断言解析器返回 `needs-verification` 且消息含选择器名（而不是 `null` 或 `success` 空）。

**涉及文件**：新增 `src/selectors.ts`；改 `neusoft.ts` / `itest.ts` / `pigai.ts` / `chaoxing.ts` / `platforms.ts`（定义 `SelectorError`、规范注释）/ `diagnose.ts`（带 `selectorsVersion`）/ 各 `*.test.ts`。

**风险/验收**：配置重构会触及所有解析器，**必须逐个平台改、逐个跑通已有单测**，避免一次性大改引入回归。验收 = 跑 `npm test` 全绿；且人为删掉某选择器后，对应平台返回 `needs-verification` 而非静默清空。

**待确认决策**：选择器配置粒度（按字段细拆 vs 按整块）——默认按“结构锚点 + 字段”两级即可。

### 2.4 浏览器启动即同步（不只通知）

**现状**
- `background.ts` 第 46–48 行：`runtime.onStartup` 只调用 `notifyFromCache()`——它只读**缓存**弹一条通知，**并不真正去拉取**平台数据。
- 真正拉取只在 `content.ts` 于平台页面 `document_idle` 自动上报、或用户在看板点“刷新当前平台”（`SYNC_ACTIVE_PAGE`）时发生。

**问题**：用户不主动访问平台，就一直不更新，容易漏作业。

**硬约束（必须先讲清）**：浏览器扩展**无法读取未打开页面的 DOM**（解析依赖 content script 注入到平台页面）。所以“启动时拉一次”只有两条现实路径——

**方案**
1. **启动重同步已打开的标签页（轻量、必做）**：`runtime.onStartup` 时 `browser.tabs.query({ url: 各平台 host })`，对每个已打开的平台标签页发送 `SYNC_ACTIVE_PAGE`（沿用现有协议，`allowAutoOpen=false` 不打断用户），让后台里开着的平台页自动刷新一次。保留现有缓存通知。
2. **看板“同步全部平台”按钮（真正的一键拉取）**：在 `popup/App.tsx` 加一个按钮——依次在各平台落地页 URL 开一个 `active:false` 的临时后台标签，等其 content script 上报 `PLATFORM_PAGE_READY`（或超时），再关掉临时标签。这样用户不手动访问也能把四个平台都拉一遍。
   - 平台落地页 URL 放进 `models.ts`/`platforms.ts` 的 `PLATFORM_LANDING`（如东软 `study.neusoft.edu.cn` 首页、批改网 `pigai.org` 我的作文页等），与现有 `PLATFORM_HOSTS` 并列。
   - **铁律不变**：临时标签只加载“列表/通知”页，绝不点“考试/交卷”按钮（沿用 chaoxing 已有的安全边界）。
3. **（可选）定时保活**：用 `browser.alarms` 每日触发一次“方案 1 的重同步”，让长期不关浏览器、但开着平台标签的会话也能保持新鲜。
4. **README 如实说明限制**：明确“启动同步仅对已在后台打开的平台标签页生效；从未打开过的平台需访问一次，或用看板‘同步全部平台’按钮”。

**涉及文件**：`background.ts`（启动 tabs 查询 + 可选 alarms）、`popup/App.tsx`（按钮 + 等待逻辑）、`models.ts`/`platforms.ts`（加 `PLATFORM_LANDING`）、`content.ts`（已支持 `SYNC_ACTIVE_PAGE`，可加一个“临时标签已就绪”回执）。

**风险/验收**：临时标签可能触发平台登录态校验/重定向——需在每个平台实测；按钮逻辑必须设超时与并发上限，避免一次开四个标签卡死。验收 = 启动后后台开着平台页能自动刷新；点“同步全部”后看板数据更新且未误点考试。

**待确认决策**：“真正的一键拉取”是否要做到（开临时标签，较重）？还是只做“重同步已打开标签”（较轻）？默认建议两者都做，按钮作为补充。

### 2.5 学习通收件箱翻页

**现状**
- `chaoxing.ts` 的 `extractChaoxingAssignments` 只读取 `notice.chaoxing.com/pc/notice/myNotice` 当前页（`readRawItems` 一次性取 `li.dataBody_item`）。
- `README.md`「已知限制」第 105 行已自承：“**学习通邮箱仅同步收件箱第一页**，未自动翻页”。
- 收件箱分页控件（通常是 `.el-pagination` / “下一页”按钮）完全没处理。

**方案**
1. **读首页后探测分页**：`readRawItems` 之后，在 iframe 内检测分页控件（`.el-pagination`、包含“下一页”的可点击节点、或页码信息文本）。
2. **循环翻页累加**：若不是末页，点击“下一页”（或设置页码）后 `waitFor` 列表重新渲染（`li.dataBody_item` 数量或内容变化），再 `readRawItems` 累加；直到末页或达到 `MAX_PAGES` 安全上限（建议 20，防无限循环）。
3. **跨页去重**：以 `li[data-id]` 为键去重（现有 `id = chaoxing:<data-id>` 天然可按 id 去重），避免翻页重复计数。
4. **只在“全部页读完”时才 `replaceAll`**：分页中途若控件失效/超时，返回 `needs-verification`（不覆盖历史缓存），而不是清空。
5. **考试详情抓取兼容**：翻页后会多出考试通知，复用现有 `mapWithConcurrency(examItems, 5, …)` 隐藏 iframe 抓取；可视情况把并发上限或总项数上限略调高。
6. **安全性**：点“下一页”只是浏览收件箱列表，不是“考试/交卷”按钮，**不违反既有铁律**。

**涉及文件**：`src/chaoxing.ts`（翻页循环 + 跨页去重 + 分页失败转 `needs-verification`）、`chaoxing.test.ts`（构造多页假 DOM 验证累加与去重）。

**风险/验收**：分页 DOM 各平台/账号可能不同，需稳健定位“下一页”；翻页动画期间要等渲染完成再读。验收 = 构造 3 页假数据，解析出全部条目且无重复；模拟“下一页失效”时返回 `needs-verification` 而非清空。
