# 东软智慧教育作业解析交接文档

## 任务目标

为 Edge 作业整合扩展实现东软智慧教育的真实作业读取能力。只纳入东软平台明确标记为“未提交”的作业，并读取作业名称、截止时间（若有）和作业详情链接。

实现应按小任务推进，每个小任务结束时记录结果并运行对应检查，降低长任务中断后的恢复成本。

## 当前状态

- 扩展框架已搭建：WXT + React + TypeScript + Manifest V3。
- 扩展源码目录：`extension/`。
- 东软平台匹配域名：`study.neusoft.edu.cn`。
- 东软适配器已实现真实解析（`extension/src/neusoft.ts`）：基于已验证的“课程详情 → 作业”可见结构，仅在解析条数与汇总总数一致时返回 `success`，仅纳入“作答中 / 未作答”；批改网 / iTEST 仍为占位，见 `extension/src/platforms.ts`。
- Content Script 在匹配页面加载后调用适配器，并将状态发送给后台，见 `extension/entrypoints/content.ts`。
- 后台仅在状态为 `success` 且带有作业数组时替换缓存；失败或待验证状态不会清除已有作业，见 `extension/entrypoints/background.ts`。
- 用户已报告登录东软；此前提供的截图显示已登录首页 `https://study.neusoft.edu.cn/index`，页面中有课程卡片，但没有显示作业列表。

- 上次验证通过：在 `extension/` 中运行 `npm run compile` 和 `npm run build`。
- Git 最近基线提交：`444595d feat: initialize homework dashboard extension`。继续前检查 `git status --short`，不要覆盖用户后续改动。

## 重要约束

- 不要求用户提供密码、Cookie、Authorization 头或会话令牌。
- 不访问或保存与作业读取无关的个人信息。
- 不猜测 API 路径、字段名或“未提交”状态文案。
- 只在平台页面明确能确认“未提交”时创建作业记录。
- 解析失败、登录失效、空白页或未知响应都不能覆盖上次成功同步的作业缓存。
- 不要把“访问首页成功”误报成“作业同步成功”。
- 用户要求分批进行；每次只完成一个可独立验证的小任务，并在 `progress.md` 记录完成情况。

## 证据缺口

需要从已登录的东软账号中取得以下非敏感页面信息：

- 作业列表所在页面的 URL 路径。
- 作业卡片或表格的 DOM 结构、作业名称、状态文字、截止时间和详情链接。
- 若列表由接口返回：请求 URL 路径、HTTP 方法、响应字段结构和状态字段含义。
- 可选：作业页面局部截图。提交或保存 HAR 前必须移除 Cookie、Authorization、用户标识及其他认证信息。

首页截图不是作业页面证据。需要用户先在 Edge 中进入有作业列表的课程/作业页面；如果无法连接当前 Edge 调试会话，可先做一个本地临时诊断入口，只在当前标签页读取并输出经过过滤的 DOM 摘要。

## 建议的小任务顺序

### 小任务 1：定位东软作业页面

- 用户在 Edge 中打开一门有作业的课程，再进入作业列表。
- 确认地址栏 URL 和页面可见的状态、标题、截止时间。
- 不修改生产解析逻辑。
- 交付：记录页面 URL 模式和必要字段证据。

### 小任务 2：采集页面结构

- 首选检查已登录标签页的 DOM 或 DevTools Network 请求。
- 若当前环境无法读取浏览器标签页，新增仅限东软域名的临时 DOM 诊断功能。
- 诊断输出仅保留标签名、class、有限的可见文本摘要、链接路径和非敏感 JSON 键；排除表单值、密码、Cookie、Authorization、token、用户标识及长随机字符串。
- 交付：一份去敏的 DOM/响应结构摘要，不保存会话凭证。

### 小任务 3：确认“未提交”规则

- 根据真实页面文字或已核实的响应字段，确认哪些状态表示未提交。
- 识别已提交、批改中、草稿、已截止等相邻状态，避免误纳入。
- 若平台没有稳定、明确的状态信号，暂停实现并报告缺口。
- 交付：状态映射表和至少一条脱敏样本。

### 小任务 4：实现东软解析器

- 只修改东软适配器；批改网和 iTEST 保持占位。
- 优先使用稳定的页面结构或平台前端实际调用的接口；避免脆弱的全页文本匹配。
- 对每项作业生成稳定 ID、标题、状态、截止时间、详情 URL 和同步时间。
- 只有成功确认列表完整且解析成功时返回 `success`。
- 交付：解析器实现及针对已知样本的测试。

### 小任务 5：构建并实测

- 运行 `npm run compile`。
- 运行 `npm run build`。
- 在 Edge 加载 `extension/.output/chrome-mv3/` 并访问东软作业页。
- 核对未提交项目、已提交项目、空列表和页面异常四种情况。
- 交付：验证结果、限制说明和必要修复。

### 小任务 6：整理版本

- 更新需求文档和 `progress.md` 的实现状态。
- 检查 `git diff`，只提交与东软适配器有关且已验证的改动。
- 提交信息建议：`feat: parse unsubmitted Neuedu assignments`。

## 已核实的解析来源（两条，互斥）

1. **首页“我的学习任务”**（`.my-task`，主来源，跨课程、无需点击任何标签）
   `<序号?><标题> 作业 截止时间：YYYY-MM-DD HH:MM:SS所属课程：<课程名> 去作答`
   解析器：`parseNeusoftHomeTasks()`（锚点定位 + 边界切割），`source: 'home'`。
2. **课程详情页 → 作业标签**（兜底，单门课程）
   `已完成 X/Y` + `<两位序号><中文标题> 课后 剩余作答次数：N 进行中 状态： 已作答|作答中|未作答 … 详情|去作答`
   解析器：`parseNeusoftAssignmentText()`（严格/宽松两级正则），`source: 'course'`，需“解析条数 === 汇总总数”才 success。

缓存合并规则见 `models.ts` 的 `mergeAssignmentsByCourse`（按课程替换 + 来源标记界定清理范围 + 同标题归属统一 + 去重）。

- `extension/src/models.ts`：作业和平台状态类型。

- `extension/entrypoints/content.ts`：页面内容脚本和后台消息发送。
- `extension/entrypoints/background.ts`：状态合并与缓存保护。
- `extension/wxt.config.ts`：Manifest 权限和允许访问的站点。
- `extension/README.md`：开发、构建、Edge 加载说明。
- `作业整合作业看板_需求文档.md`：产品需求和当前实现状态。
- `progress.md`：跨会话开发进度。
